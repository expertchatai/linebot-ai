# ขั้นตอนทดสอบก่อนเปิดใช้งานจริง

ทดสอบทุกข้อใน **TEST MODE** ให้ผ่านก่อน จากนั้น Super Admin จึงตั้ง `ALLOW_LIVE_MODE=true` แล้วสั่ง `MODE LIVE`

## A. เตรียมระบบ
- [ ] `npm test` ผ่านทั้งหมด
- [ ] `/api/jobs/tick` ตอบ `ok` และ pg_cron รันทุกนาที (ดูได้ที่ Supabase → `cron.job_run_details`)
- [ ] Dashboard ต้อง login ก่อนเข้าได้ และถ้าใส่รหัสผ่านผิดต้องเข้าไม่ได้
- [ ] ยิง webhook ด้วยลายเซ็นปลอมแล้วต้องได้ 401 (ทั้ง LINE และ Messenger)

## B. ข้อมูลและการอนุมัติ
- [ ] แก้ข้อมูลตาม [KNOWLEDGE_AUDIT.md](KNOWLEDGE_AUDIT.md) ใน Google Sheets ให้เรียบร้อย
- [ ] ชุดแรกเข้ากลุ่ม Admin ตรวจครบทุกรายการแล้วจึงอนุมัติ
- [ ] แก้ 1 แถวใน Sheet แล้วรอ: ข้อความขออนุมัติต้องมาหลังหยุดแก้ไขประมาณ 1–2 นาที และแสดงข้อมูลเดิมเทียบข้อมูลใหม่
- [ ] แก้ 3 แถวติดกันภายใน 1 นาที: ต้องได้ **ชุดเดียว**
- [ ] ปฏิเสธรายการหนึ่ง: `ASK` เรื่องนั้นแล้ว AI ต้องไม่ใช้ข้อมูลใหม่ และระบบต้องไม่เสนอเนื้อหาเดิมซ้ำ
- [ ] กดอนุมัติจากโทรศัพท์สองเครื่องพร้อมกัน: ต้องสำเร็จเพียงครั้งเดียว
- [ ] ผู้ที่ไม่ใช่ Admin กดปุ่มอนุมัติแล้วต้องถูกปฏิเสธ
- [ ] `ADD` ผ่าน LINE: ข้อมูลต้องยังไม่ถูกใช้จนกว่าจะได้รับอนุมัติ

## C. AI ตอบลูกค้า (ใช้ `ASK` หรือหน้าทดลองถาม AI ก่อน จากนั้นทดสอบด้วยบัญชีทดสอบจริง)
- [ ] เพิ่มบัญชีทดสอบ: พิมพ์ `#MYID` ใน OA ลูกค้า แล้วใช้คำสั่ง `TESTER ADD <id>` ใน OA ผู้ดูแล
- [ ] บัญชีที่ไม่ใช่บัญชีทดสอบส่งข้อความเข้ามาแล้ว AI ต้อง **ไม่ตอบ**
- [ ] "ติดฟิล์ม Rolex Datejust ราคาเท่าไหร่" → ตอบ 6,500 (oyster) / 8,900 (jubilee) และใช้คำลงท้าย "ครับ"
- [ ] "ติดฟิล์ม Omega ราคาเท่าไหร่" → ต้องไม่เดาราคา และขอรุ่นหรือภาพเพิ่ม
- [ ] "ล้างเครื่อง Rolex Sub ราคา" → ตอบว่า "เริ่มต้น 10,500 บาท ไม่รวมอะไหล่"
- [ ] "ติดฟิล์ม + ล้างเครื่อง Datejust รวมเท่าไหร่" → ต้องไม่รวมราคาให้เอง
- [ ] "How much is film for a Patek?" → ตอบเป็นภาษาอังกฤษ
- [ ] ส่ง 3 ข้อความติดกันภายใน 5 วินาที → ต้องได้คำตอบเดียว
- [ ] ส่งข้อความที่สองหลังจากได้คำตอบแรกไปแล้ว → AI ต้องไม่ทักทายซ้ำ
- [ ] ส่งภาพนาฬิกา → ได้ความเห็นเบื้องต้นพร้อมระบุว่ายังไม่แน่นอน และ **ไม่รับรองว่าแท้หรือปลอม**
- [ ] ส่งข้อความเสียงถามเวลาเปิดร้าน → ตอบได้ถูกต้อง
- [ ] ส่งวิดีโอ → ส่งต่อเจ้าหน้าที่ทันทีโดยไม่วิเคราะห์
- [ ] "นาฬิกาที่ส่งซ่อมเสร็จหรือยัง" → ส่งต่อเจ้าหน้าที่ทันที
- [ ] คำถามที่ไม่มีในข้อมูล เช่น "ซ่อมกระจกแตก Hublot ราคา" → ส่งต่อเจ้าหน้าที่
- [ ] "อยากนัดล้างเครื่องวันเสาร์" → AI ถามชื่อและเบอร์ แล้วบันทึกคำขอโดย **ไม่ยืนยันนัด**

## D. Handoff และการแจ้งเตือน
- [ ] การแจ้งเตือนแรกเข้ากลุ่ม Admin ทันที พร้อมสรุปประเด็นและร่างคำตอบ
- [ ] ถ้าไม่มีคนกดรับเรื่อง ต้องเตือนซ้ำทุก 15 นาที (ช่วง 08:30–20:00) และไม่เตือนนอกเวลา
- [ ] กด "รับเรื่องแล้ว" → การเตือนหยุด และบันทึกชื่อกับเวลา ถ้าคนที่สองกดซ้ำต้องเห็นว่าใครรับไปแล้ว
- [ ] ระหว่างที่ AI หยุดอยู่ ลูกค้าส่งข้อความมาแล้ว AI ต้องไม่ตอบ
- [ ] คำสั่ง `OFFAI` แสดงรายการแชท และ `ONAI` ต้องมีขั้นยืนยันก่อน จากนั้น AI จึงกลับมาตอบ

## E. การควบคุม
- [ ] `AI LINE OFF` → แสดงผลกระทบก่อน กดยืนยันแล้ว AI ต้องหยุดตอบทุกแชทใน LINE
- [ ] `TOPIC OFF brand Rolex` → ถามเรื่อง Rolex แล้วต้องถูกส่งต่อเจ้าหน้าที่
- [ ] Admin ทั่วไปสั่ง `MODE LIVE` หรือ `ADMIN ADD` แล้วต้องถูกปฏิเสธ
- [ ] สั่ง `MODE LIVE` ขณะที่ `ALLOW_LIVE_MODE=false` แล้วต้องถูกปฏิเสธ

## F. ความทนทาน
- [ ] ทำให้ Sheets อ่านไม่ได้ชั่วคราว (เช่น ถอนสิทธิ์ Service Account) → กลุ่มได้รับแจ้งเตือน และ AI ยังตอบได้
- [ ] คืนสิทธิ์ → ถ้าข้อมูลตรงกันต้องได้ข้อความ "กลับมาใช้งานได้" ถ้าไม่ตรงต้องได้ชุดให้เลือกข้อมูล
- [ ] ใส่ `GEMINI_API_KEY` ผิด → ลูกค้าได้ข้อความว่าเจ้าหน้าที่จะติดต่อกลับ, มีการส่งต่อ และ Super Admin ได้รับแจ้ง error
- [ ] ตรวจตาราง `message_buffer` / `chat_context` ใน Supabase ต้องไม่มีข้อความค้างนานเกิน 10 / 30 นาที

## G. เปิด Live
- [ ] Super Admin ตั้ง `ALLOW_LIVE_MODE=true` บน Vercel แล้ว Redeploy
- [ ] สั่ง `MODE LIVE` → ตรวจผลกระทบ → กดยืนยัน → กลุ่ม Super Admin ได้รับข้อความยืนยัน
- [ ] ถ้ามีปัญหา: `MODE TEST` หรือ `AI LINE OFF` หยุด AI ได้ทันที
